# Release v2.6.11 — GMweb Bridge Reliability (Pass 2 start)

**versionCode 53 · Room schema v6 (unchanged) · No new features**

Fixes the root cause of the Eve-panel failure
`failed (http_503: android_gateway_unreachable)`: the phone's GMweb pull
loop dying silently (app swiped away, Doze freezing the long-poll socket,
process death) so GMweb sees "no device polling" and refuses every send.

Diagnosis (verified in code, both repos): the 503 is generated by GMweb's
`/send` pre-handler when the pull bridge is dark (`outbox.readyState()` →
`waitingPhones == 0 && lastPullAt older than 90s`). The v2.6.10 status-code
changes live on the phone→? direction (`/api/v1/sms/send`) and never touch
this path. **No GMweb change is required.**

## Fixes — make the pull loop survive everything

### 1. Wake lock per pull cycle (`OutboxPoller`)

A partial wake lock (`Messages:OutboxPoller`) is acquired for exactly the
active part of each cycle — long-poll (≤30s server hold) + delivery + ack —
and released in `finally` before the idle gap. In Doze, the CPU sleeps
between maintenance windows and an in-flight long-poll socket dies silently;
now the radio+CPU stay alive precisely while we promised the server we are
reachable, and the device sleeps normally between cycles (battery cost
proportional to bridge duty, not wall-clock). 90s lock timeout is the
anti-leak safety net.

### 2. Alarm watchdog on service death (`GatewayService`)

`START_STICKY` revival is delayed/unreliable under Doze. `onDestroy` now
arms `setExactAndAllowWhileIdle` (+15s) that re-fires `ACTION_START` through
`PendingIntent.getForegroundService` — revived even from Doze. Guarded: only
when the gateway is still consented **and** desired-enabled (a user Stop
through ACTION_STOP stays dead because `prefs.isEnabled` already flipped).
Falls back to inexact `setAndAllowWhileIdle` when exact-alarm permission is
missing (API 31+).

### 3. Honest FGS type: `dataSync|specialUse`

`specialUse` alone gave the OS no policy signal for the pull bridge — the
actual work is a long-running network sync. The service now declares
`dataSync` (API 34+ combines both), which is the type Doze policy expects
for exactly this workload; manifest permissions `WAKE_LOCK` and
`FOREGROUND_SERVICE_DATA_SYNC` added.

### 4. Bridge telemetry on the persistent notification

The "SMS Gateway Active" notification now shows live GMweb bridge state —
`GMweb bridge: live / delivering / retrying… / idle` — so "the panel says
503" is diagnosable from the lock screen: if it does not say *live*, the
phone side is the problem, not Eve or GMweb.
